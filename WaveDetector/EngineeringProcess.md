# Overview
The goal in developing the WaveDetector was to provide an easy and intuitive way to use a hand to both skip and replay songs and adjust volume all with TOF distance sensors. I used two sensors angled slightly outward to ensure one would activate first and they were distinctly ordered, even with fast swipes.
# Design Process
For this portion of the project, I was in charge of setting up this swiping and volume sensing, as well as creating a simple server that our serial receivers can easily POST requests to in order to interact with the Spotify API. I saw three stages that would need to be completed to have a functioning skeleton.
1. Set up Arduino ESP32 C code to detect waves, change to volume mode, and adjust volume. 
2. Create Serial receiver logic to relay signals from connected Arduino to web server to interact with Spotify API
3. Set up simple web server with endpoints to correspond to different spotify functionalities. 
# Arduino Code
The actual ESP32 C++ code is simple in nature. The setup of the TOF sensors is a bit complicated at first, as you have to use the XSET pins to shut down each sensor and boot them one at a time to assign serial addresses so they can be distinguished from one another. After that, you can use lox.begin and subsequent methods on the object to get a reading. I used a value of 30cm as my baseline, meaning it will detect if it gets a reading closer than that. You may have to adjust based on your setup and how far away your nearest object is from the sensor at rest. After that, I stored the last seen sensor and if the other sensor reads within 2 seconds, a swipe is registered in the respective direction. For the volume, I stored all readings from the first sensor and checked whether the average over x amount of time was lower than a certain number. All of these parameters are tweakable and were used because they worked best for us. If it reached below that number, the storage was reset and mode was changed which activated a different control flow in the loop() function. This flow just read distance from the TOF sensor, and if below a certain threshold used Spotify API to adjust volume on host computer corresponding to distance of hand from sensor. More intricate detail can be found by checking the WaveDetector/src/DistanceSensorTheremin.ino source code file.
# Serial Receiver
The serial receiver is very simple. All it does is use serial.read in a python while True loop to check serial output from the board. It analyzes this output for one of the keywords NEXT PREV or VOL and sends the corresponding data to the web server. This could have been integrated with the Express server if I had time, but reading serial input in Python was easier although it makes  a somewhat convoluted data flow. 
# Web Server
The web server is written with JS and Express.js to perform some simple functions and some less simple ones. The Spotify login credentials were a total pain to get, which I will discuss in the next section. All the server does is host POSTable endpoints for the serial receiver to interact with, then sends the command to the corresponding Spotify endpoint along with authentication credentials.
# Spotify API and other challenges
The main challenge of this project was the Spotify API. We used their documentation, which in my opinion is somewhat lacking, to build an Express server with a simple client ID and secret in the body for authentication. I then discovered that this authentication method does not allow you to control a host computer's behavior, only read artists, song names, and other public info. The resulting control flow for the more advanced authentication was quite annoying, and requires the user to go to the /login page to use the third party spotify login flow which then provides a code for the site. The code is then converted into login tokens which are stored serverside. In the future, I'd enter them into the env file for longer term storage. 
# Two Board Problem
The reason we are using two different ESP32 board is because the night before our project was due, the serial interactive ports on our Arduino S3 stopped working. This forced us to pivot to the current setup, which uses two different computers running serial monitors. This setup has some benefits in allowing us to not integrate the two .ino files, as the one running the ML model has somewhat more complicated code.
